Linux Command Line Confidence · Glossary

Command Name Origins

What each command is short for — because a name that means something is a name you remember.

Why they're all so short

Unix — where these commands were born in the early 1970s — grew up on teletypes: printers-with-keyboards that typed slowly onto paper, one character at a time. Every keystroke cost effort and every printed character cost time, so the culture prized brevity. Commands became short, lowercase, and abbreviated: ls not list, cp not copy. That terseness stuck, and it's why the terminal can feel cryptic at first. Once you know what the abbreviations stand for, the fog lifts.

Reading files (Lesson 0003)

CommandShort forThe idea
catcatenate (concatenate)Its real job is joining files end-to-end. Printing a single file is just the simplest case — nothing to do with the animal.
lessa pun on moreAn older pager was called more. Someone wrote a better one and named it less — "less is more." It scrolls through long files without loading all of them.
more"more"The original pager: shows one screenful, then prompts --More-- for the next.
headhead = topShows the top of a file (its first lines).
tailtail = endShows the end of a file (its last lines). tail -f "follows" a file live as it grows.

Finding things (Lesson 0004)

CommandShort forThe idea
find"find"Plain English — searches for files by name, through a folder and all its subfolders.
grepglobal / regular expression / printFrom the g/re/p command in the old ed editor: search every line (global) for a pattern (regular expression) and print the matches. So common it became its own tool.

Getting help (Lesson 0005)

CommandShort forThe idea
manmanualShows the manual page for a command. Opens in less, so q quits.
--help"help"Long-form flag most commands understand; prints a quick usage summary in place.
apropos"concerning" (English/French)Searches manual descriptions by keyword — apropos disk finds commands "concerning disk." Same as man -k.

Making & changing files (Lesson 0006)

CommandShort forThe idea
mkdirmake directoryMakes a new folder. -p = parents (make the whole nested path).
touch"touch"Its original job is updating a file's timestamp — "touching" it. Making an empty file is what happens when you touch one that doesn't exist yet.
cpcopyCopies a file. -r (recursive) copies a whole folder.
mvmoveMoves a file — and renaming is just moving it to a new name.
rmremoveDeletes permanently (no trash). -r = recursive, -f = force.
rmdirremove directoryRemoves a folder only if it's empty — a built-in safety net.

Pipes & redirection (Lesson 0007)

Symbol / commandShort forThe idea
>arrow into a filePoints output at a file (overwrites it).
>>double arrow = add onAppends output to the end of a file.
|a "pipe"Data flows through it like water through plumbing — output of one command becomes input of the next. The metaphor its inventor intended.
echo"echo"Echoes your words back, like a shout in a canyon.
wcword countCounts lines/words/characters. -l = lines.
sortsortPuts lines in order (-n numeric, -r reverse).

Permissions (Lesson 0008)

Command / termShort forThe idea
chmodchange mode"Mode" is the traditional Unix name for a file's permission bits — chmod changes them.
chownchange ownerReassigns which user owns a file (usually needs root).
sudosuperuser do"Do this one command as the superuser" — borrows root's unlimited power for a single command.
rootthe root of the treeThe whole file system hangs off /, the tree's root; the all-powerful account that owns it took the same name.

YAML & Docker (Lesson 0009)

TermShort forThe idea
YAMLYAML Ain't Markup LanguageA recursive acronym — the name contains itself. It launched in 2001 as "Yet Another Markup Language" (a joke about how many there were), then was renamed in 2002 to stress that it describes data, not documents.
Dockerdock workerFrom shipping: a dock worker loads standardised containers onto ships. The whole metaphor is the point — a container packs an app so it runs the same anywhere, like a shipping container fits any vessel.
composecomposeYou compose an application out of several containers, the way you compose music from parts — one file describing how the pieces fit together.
imageimageLike a disk image: a frozen snapshot of an app and everything it needs. A running copy of an image is a container.
volumevolumeBorrowed from storage — a "volume" is a mounted chunk of disk. Here it's a folder from the host mounted inside the container.
PUID / PGIDprocess user / group IDWhich user and group the app should act as — so files it creates carry permissions you can actually use (see Lesson 0008).
