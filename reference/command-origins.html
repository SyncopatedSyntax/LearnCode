Command Name Origins

What each command is short for — because a name that means something is a name you remember.

Why they're all so short

Unix — where these commands were born in the early 1970s — grew up on teletypes: printers-with-keyboards that typed slowly onto paper, one character at a time. Every keystroke cost effort and every printed character cost time, so the culture prized brevity. Commands became short, lowercase, and abbreviated: ls not list, cp not copy. That terseness stuck, and it's why the terminal can feel cryptic at first. Once you know what the abbreviations stand for, the fog lifts.

Reading files (Lesson 0003)

CommandShort forThe idea
catcatenate (concatenate)Its real job is joining files end-to-end. Printing a single file is just the simplest case — nothing to do with the animal.
lessa pun on moreAn older pager was called more. Someone wrote a better one and named it less — "less is more." It scrolls through long files without loading all of them.
more"more"The original pager: shows one screenful, then prompts --More-- for the next.
headhead = topShows the top of a file (its first lines).
tailtail = endShows the end of a file (its last lines). tail -f "follows" a file live as it grows.

Finding things (Lesson 0004)

CommandShort forThe idea
find"find"Plain English — searches for files by name, through a folder and all its subfolders.
grepglobal / regular expression / printFrom the g/re/p command in the old ed editor: search every line (global) for a pattern (regular expression) and print the matches. So common it became its own tool.
