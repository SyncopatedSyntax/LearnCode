Reading Files Without Changing Them

Four safe ways to look inside a file — cat, less, head, tail — and the words hiding inside their names.

Where this fits

You can move around (Lesson 0001) and connect to the NAS (Lesson 0002). The next safe skill is reading what's inside a file — the last piece of "explore anything without changing anything."

All read-only. These four commands only display a file's contents. They never edit, move, or delete. Safe on your own computer and safe on the NAS.

One habit worth adopting: I'll tell you what each command's name is short for as we go. A name that means something is far easier to remember than a random two letters. The full list lives in the Command Name Origins glossary.

cat — dump a whole file

cat prints an entire file to the screen at once.

$ cat notes.txt
Buy milk
Call the plumber
Renew NAS backup

Name origin: cat is short for concatenate — "to join end-to-end." Its original purpose was gluing several files together into one stream; showing a single file is just the simplest version of that. (Nothing to do with the animal — a happy accident.) You can see the joining behavior with two files:

$ cat part1.txt part2.txt

cat is perfect for short files. For a long one, the whole thing scrolls past faster than you can read — which is exactly the problem the next command solves.

less — scroll through a long file

less opens a file in a pager: a scrollable view you can move through at your own pace.

$ less /var/log/some-long.log

Once it's open:

KeyDoes
SpaceDown one screen
↑ / ↓Up / down one line
/wordSearch for "word" (press Enter)
qQuit — back to your prompt
The one thing that traps everyone: less takes over your whole screen, and it's not obvious how to get out. The answer is q. Remember that one key and less will never strand you.

Name origin: there was an older pager called more (it showed one screen and prompted --More--). Someone later wrote a more capable version and named it less, as a wink at the saying "less is more." Unlike cat, it doesn't load the whole file at once, so it stays fast even on huge logs.

head and tail — just the ends

Sometimes you don't want the whole file — just a peek at the start or the end.

$ head config.txt     # first 10 lines
$ tail config.txt     # last 10 lines
$ head -n 5 config.txt   # first 5 lines instead

Name origins: pure anatomy. head shows the top of the file; tail shows the bottom. Easy to remember because the metaphor is doing all the work.

One especially handy trick — tail -f (for follow) keeps watching a file and prints new lines as they're added. It's the standard way to watch a log update live:

$ tail -f /var/log/some.log
# ...new lines appear as they happen...
# press Ctrl+C to stop watching

One safety note

Don't cat a file that isn't text. If you cat a photo, a database, or another binary file, the terminal tries to "print" random bytes and your display can fill with garbage and stop behaving. It's harmless to the file — but to fix your terminal, just type reset and press Enter (even if you can't see what you're typing). When unsure whether a file is text, use less instead — it handles this more gracefully.

Try it

On your own computer or on the NAS — both safe:

  1. cd somewhere with text files (your home directory is fine).
  2. cat a short one and read it.
  3. Open something longer with less, scroll with Space, then quit with q. Practice that q until it's reflex.
  4. Run head and then tail on the same file. Notice you're seeing opposite ends.

Check your recall

Answer from memory first, then reveal.

cat is short for what — and what's its real purpose?

Concatenate — joining files end-to-end. Printing one file is just the simplest case.

You opened a file in less and your prompt is gone. How do you get back?

Press q to quit the pager and return to your prompt.

Which command shows the last lines of a file, and which flag watches it live?

tail shows the end; tail -f follows it as new lines are added.

Your terminal fills with garbage after viewing the wrong file. What fixes it?

Type reset and press Enter, even if the text is unreadable as you type.
