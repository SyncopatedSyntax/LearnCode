Linux Command Line Confidence · Lesson 0002

SSH Into Your NAS

Open a shell on your Synology from your own computer, look around with commands you already know, and leave without touching a thing.

What SSH actually is

SSH (Secure Shell) opens a terminal on another machine over the network. You type on your laptop, but the commands run on the NAS. That's the whole idea: the same pwd, ls, and cd from Lesson 0001 now let you walk around the NAS's file system as if you were sitting at it.

This whole lesson is read-only. Every command here only looks — nothing creates, moves, deletes, or changes settings on the NAS. You can run all of it safely.

The connect command

Open a terminal on your own computer (Terminal on Mac, or PowerShell on Windows — both have ssh built in). The command has a simple shape:

$ ssh admin@192.168.1.50

Reading it left to right:

  • ssh — the program that makes the connection
  • admin — your DSM account name (must be in the NAS's administrators group)
  • @ — just a separator: "this user at that machine"
  • 192.168.1.50 — your NAS's address on your network
Which address? Whatever you already use to reach your NAS — its IP (like 192.168.1.50) or its network name. You can find the IP in DSM under Control Panel → Network, or in your router. Since you already SSH in sometimes, use the same address and account you use now.

If your NAS uses a non-standard SSH port (some setups change it away from the default 22), add -p and the number:

$ ssh -p 2222 admin@192.168.1.50

What you'll see the first time

1. A fingerprint question

On the very first connection to a machine, you'll see something like:

The authenticity of host '192.168.1.50' can't be established.
ED25519 key fingerprint is SHA256:9f2c...
Are you sure you want to continue connecting (yes/no)?

Type yes and press Enter. This records the NAS's identity so that next time, SSH can confirm it's really the same machine and warn you if something impersonates it. For your own NAS on your own network, yes is the right answer. You'll only see this once per machine.

2. A password prompt

admin@192.168.1.50's password:

Type your DSM password and press Enter.

Nothing appears as you type — no dots, no stars, no moving cursor. This is normal and deliberate (it hides your password's length). Type it anyway and press Enter. This is the one moment that startles every beginner, so now you know.

3. You're in

The prompt changes to show the NAS's name — proof you're now "on" the other machine:

admin@YourNAS:~$

Look around (safely)

Two of these you already know from Lesson 0001; two are new. All four only read information:

$ whoami      # which account am I logged in as?
$ hostname    # what machine am I on? (confirms it's the NAS)
$ pwd         # where am I? (your home directory on the NAS)
$ ls          # what's in here?

Running hostname right after connecting is a great habit — it's a one-second sanity check that you're about to type commands on the NAS and not accidentally on your own laptop.

Leave cleanly

$ exit

This closes the SSH session and drops you back to your own computer's terminal (your prompt name changes back). Pressing Ctrl+D does the same thing. That's it — you were a guest, you looked around, you left.

What we're deliberately not doing yet

To keep this safe, this lesson stays away from anything that changes the NAS: sudo (running as superuser), deleting or moving files (rm, mv), changing permissions, and installing software. Those are real skills worth learning — just later, on purpose, once looking around feels routine.

Try it

  1. Open your computer's terminal and connect with ssh your-account@your-nas-address.
  2. Get past the password prompt (remember: invisible typing is normal).
  3. Run hostname and confirm it shows your NAS's name.
  4. Run whoami, pwd, then ls. Notice this is the same navigation from Lesson 0001 — just on a different machine.
  5. Type exit and confirm your prompt returns to your own computer.

Check your recall

Answer from memory first, then reveal.

In ssh admin@192.168.1.50, what are the three parts?

The user account (admin), the separator @, and the machine's address (192.168.1.50).

You start typing your password and nothing shows on screen. What do you do?

Keep typing and press Enter — hidden input is normal and intentional for passwords.

Which command confirms you're actually on the NAS and not your own computer?

hostname — it prints the name of the machine you're currently connected to.

How do you end the SSH session and return to your own computer?

Type exit (or press Ctrl+D).
