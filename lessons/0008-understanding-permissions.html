Linux Command Line Confidence · Lesson 0008

Understanding Permissions

Decode -rw-r--r--, defuse "permission denied," and finally learn what sudo actually is.

Closing a loop from Lesson 0001

Back in Lesson 0001, ls -l showed you lines like this, and we set the cryptic first column aside:

-rw-r--r--  1 you  staff  220 Jun 10 18:02 notes.txt

Time to decode it. Permissions are also where the most common scary error comes from — Permission denied — and once you can read them, that error stops being spooky and starts being information.

Reading permissions is completely safe — it's just more ls -l. Changing them is the part with teeth; we'll practice that only in a sandbox on your own machine, and not on the NAS at all.

Reading the string

Ignore the first character (you know it: - file, d directory). The remaining nine characters are three groups of three:

 rw-        r--        r--
owner      group      others
  • Owner — the user who owns the file (usually its creator)
  • Group — a named set of users the file belongs to
  • Others — everyone else on the machine

Each group of three answers, in order: can they read it? write (change) it? execute (run) it? A letter means yes; a - means no.

So -rw-r--r-- reads: a regular file; the owner can read and write; the group can only read; everyone else can only read. That's it — you can now decode any permission string you'll ever see.

LetterOn a fileOn a directory
r — readOpen and view itList what's inside (ls)
w — writeChange or overwrite itCreate/delete files inside it
x — executeRun it as a programEnter it (cd into it)

The directory column explains a classic head-scratcher: if a folder is missing x for you, you can't even cd into it.

So that's what "permission denied" means

When you see it, the system is saying exactly one thing: the account you're logged in as doesn't have the needed letter (r, w, or x) on that file or folder. Nothing is broken. Your move is to look:

$ ls -l blocked-file.txt
-rw-------  1 root  root  512 Jun 12 10:00 blocked-file.txt

Owner is root, and only the owner has any access — so your account, being "others," gets nothing. Mystery solved by reading, not guessing. (On the NAS you'll see this often: many system files belong to root, and being denied is the system working as designed.)

Who is root? The superuser — the one account with unlimited power over the machine. Name origin: everything in Linux hangs off the top directory /, called the root of the file-system tree; the all-powerful account that owns that tree took the same name.

sudo — explained, not yet used

You'll constantly see commands online prefixed with sudo. Now you can decode it:

Name origin: sudo = superuser do — "do this one command as the superuser." It temporarily borrows root's unlimited power for a single command, asking for your password to confirm.

Understanding sudo is safe. Running it removes every guardrail. With sudo, "permission denied" stops protecting you — including from typos. Per your standing rule: we don't use sudo on the NAS in this course until it's a deliberate, eyes-open choice. When a tutorial says sudo something, that's your cue to slow down and understand the command first — or paste it to me.

Changing permissions: chmod

The tool for changing permissions is chmod. The friendly form is symbolic — who ± what:

$ chmod u+x script.sh     # give the user (owner) execute
$ chmod go-w notes.txt    # remove write from group and others
  • Who: u = user (owner), g = group, o = others, a = all
  • Direction: + add, - remove
  • What: r, w, x

Name origin: chmod = change mode — "mode" is the traditional Unix name for a file's permission bits. Its sibling chown = change owner reassigns the owner itself (that one usually needs root, and we're leaving it alone for now).

One more decoding skill: tutorials love numeric forms like chmod 755. The numbers are just the same rwx bits added up per group — r=4, w=2, x=1. So 7 = 4+2+1 = rwx, 5 = 4+1 = r-x, and 755 = rwxr-xr-x (owner everything; group and others read+enter). You don't need to write these yet — but now they're not gibberish.

Try it — in a sandbox

Same pattern as Lesson 0006: everything inside a throwaway folder on your own machine.

$ mkdir ~/sandbox && cd ~/sandbox
$ touch test.txt
$ ls -l                       # read its permission string
$ chmod u+x test.txt
$ ls -l                       # spot the new x in the owner triplet
$ chmod go-r test.txt
$ ls -l                       # group and others just lost read
$ cd ~ && rm -r sandbox       # tidy up

Watching the string change as you flip bits is the fastest way to make the notation stick.

Check your recall

Answer from memory first, then reveal.

In -rw-r--r--, who can do what?

Owner reads and writes; group only reads; everyone else only reads.

What are the three "who" groups a permission string describes?

The owner, the group, and others — three letters (rwx) for each.

What does "permission denied" actually mean?

Your account lacks the needed r, w, or x on that file or folder.

What is sudo short for, and what does it do?

Superuser do — runs one command with root's unlimited power.

On a directory, what does the x permission allow?

Entering it — without x you can't even cd into the folder.
