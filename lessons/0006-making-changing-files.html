Linux Command Line Confidence · Lesson 0006

Making & Changing Files

Create, copy, rename, and delete — plus the two or three habits that keep "delete" from ever meaning "disaster."

A line worth naming

Every command in Lessons 0001–0005 only looked. From here on, commands change things — and the terminal has no Recycle Bin and no undo. That's not a reason to be nervous; it's a reason to build a few safety habits now that protect you for life.

Not read-only anymore. Practice everything here on your own computer, inside a throwaway folder you're happy to delete. Do not run these on the NAS or in system folders while you're learning — we'll bring skills to the NAS only once they're second nature.

The safe creators: mkdir and touch

These only make things, so they're low-risk — a good place to start.

mkdir — make a directory

$ mkdir project
$ mkdir -p reports/2026/q3    # make the whole nested path at once

Name origin: mkdir = make directory — literally "mk" + "dir." The -p flag is for parents: it creates every parent folder in the path that doesn't exist yet.

touch — create an empty file

$ touch notes.txt

If notes.txt doesn't exist, this makes an empty one.

Name origin: touch's original job is updating a file's "last modified" timestamp — touching it to mark it as changed just now. Creating an empty file is simply what happens when you "touch" a file that isn't there yet.

Copy and rename: cp and mv

These can overwrite, so they earn a little more care.

cp — copy

$ cp report.txt report-backup.txt      # copy a file
$ cp -r project project-copy           # copy a whole folder (-r)

Name origin: cp = copy. Copying a folder needs -r — the same recursive flag you met in grep and find (Lesson 0004): "this and everything inside it."

mv — move and rename

$ mv report.txt archive/       # move a file into a folder
$ mv draft.txt final.txt       # rename (move it to a new name)

That second line is the surprise: renaming is moving — you're moving the file to a new name in the same place.

Name origin: mv = move.

Both can silently overwrite. If the destination already exists, cp and mv replace it without asking — and that's gone with no undo. While learning, add -i (interactive): cp -i / mv -i ask for a yes before overwriting.

Delete: rm — the one to respect

$ rm oldfile.txt

Name origin: rm = remove.

There is no trash and no undo. rm doesn't move a file to a bin you can recover from — it deletes it. Gone means gone. This is the single most important thing to internalise in this lesson.

Two flags multiply its power — and its danger:

  • rm -r folder — recursive: delete a folder and everything inside it.
  • rm -f — force: delete without any warnings or prompts.

Combined as rm -rf, they force-delete an entire tree with zero confirmation. It's a normal tool that professionals use — but never point it at a path you haven't read twice, never at /, and never with a wildcard you haven't checked.

Two gentler options:

  • rm -i file — interactive: asks before each delete. A great habit while learning.
  • rmdir folder — remove directory, but only if it's empty. It refuses otherwise, which makes it a built-in safety net for tidying up empty folders.

The habits that keep you safe

  1. Sandbox it. Practice destructive commands only in a throwaway folder on your own machine.
  2. Use -i while learning. On cp, mv, and rm, it asks before it overwrites or deletes.
  3. ls a wildcard before you rm it. Run ls *.tmp first to see exactly what rm *.tmp would hit. (Your Lesson 0001 skill, used as a seatbelt.)
  4. Read the path twice. Especially before any rm -rf. Never on the NAS or system folders while learning.

Try it — in a sandbox

Everything happens inside ~/sandbox, which you delete at the end, so nothing else can be touched:

$ mkdir ~/sandbox && cd ~/sandbox    # a safe playground
$ touch a.txt b.txt                  # create two empty files
$ mkdir backup                       # a folder
$ cp a.txt backup/                   # copy a.txt into it
$ mv b.txt c.txt                     # rename b.txt to c.txt
$ ls -R                              # look at what you built
$ rm c.txt                           # delete one file
$ cd ~ && rm -r sandbox              # remove the whole playground

Notice the last line uses rm -r deliberately, on a folder you created for exactly this purpose. That's the safe way to meet a powerful command.

Check your recall

Answer from memory first, then reveal.

What makes rm more dangerous than deleting in a file manager?

There's no trash and no undo — rm deletes permanently, immediately.

You're about to run rm *.log. What's the safe step first?

Run ls *.log first to see exactly which files that pattern matches.

How do you rename a file — and why that command?

mv oldname newname — renaming is just moving a file to a new name.

What does adding -i to cp, mv, or rm do?

Makes it interactive — it asks for confirmation before overwriting or deleting.

What do the -r and -f flags mean for rm?

Recursive (delete a folder and its contents) and force (no prompts or warnings).
