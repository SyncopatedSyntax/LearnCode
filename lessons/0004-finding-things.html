Linux Command Line Confidence · Lesson 0004

Finding Things

Two searches that end the guessing: find locates files by name, grep hunts for text inside them.

Where this fits

So far you can read a file when you already know its name and where it lives (Lesson 0003). But the terminal's real power shows up when you don't know — "where did that config file go?" or "which file mentions my NAS's IP?" These two commands answer exactly those questions.

Still read-only. find and grep only search — they locate and display, never change. Safe on your own computer and on the NAS.

The one distinction to hold onto

Everything else follows from this:

  • find searches for files by their name — the label on the folder.
  • grep searches for text inside files — the words on the pages.

Lost the file? find. Know a phrase that's in it but not which file? grep.

find — locate files by name

The shape is find <where> -name "<pattern>":

$ find . -name "notes.txt"
./Documents/notes.txt

Reading it:

  • find — the command
  • . — where to start looking (the . from Lesson 0001 — "here"). find then searches this folder and every folder inside it, all the way down.
  • -name "notes.txt" — what name to match

The real power is wildcards. * means "any characters," so you can search by pattern:

$ find . -name "*.log"      # every file ending in .log, anywhere below here
$ find ~ -name "budget*"    # files starting with "budget", under your home dir
Quote patterns with * ("*.log", not *.log). Without quotes the shell tries to expand the * itself before find ever sees it, which can give confusing results. Quotes hand the pattern to find untouched.

You can also match by type — -type d for directories, -type f for regular files:

$ find . -type d -name "backup*"    # directories named backup-something

Name origin: find is plain English — like exit, one of the pleasantly literal ones. It finds things.

grep — search inside files

The shape is grep "<text>" <file>. It prints every line that contains the text:

$ grep "error" server.log
[08:14] error: connection refused
[09:02] error: timeout

Three flags carry most of the weight:

FlagShort forEffect
-iignore caseMatch "Error", "ERROR", "error" all the same
-rrecursiveSearch every file in a folder and its subfolders
-nnumberShow the line number of each match

Combined, they answer real questions. "Which file anywhere under here mentions my NAS, case aside, and on what line?"

$ grep -rin "synology" .
./notes/setup.md:12:My Synology NAS lives at ...

Name origin — the good one: grep comes from an old Unix text editor called ed. To search a file there, you typed g/re/p — g for global (every line), re for the regular expression (the search pattern), p for print. People used it so constantly that it became its own tool, keeping the name. So grep literally spells out "globally find this pattern and print it." Knowing that, the name stops being random noise.

Two practical notes

Search from a folder, not from /. Starting a find or grep -r at the system root (/) crawls the entire machine — slow, and noisy with "permission denied" lines. Start from . (here) or ~ (your home) instead. On the NAS especially, keep searches pointed at a specific folder you care about.
We're only using these to look. find has options that can delete or run commands on what it matches (-delete, -exec) — real power, real risk. We're deliberately not touching those yet, same as the NAS rule: locate first, act later and on purpose.

Try it

On your own computer is fine:

  1. cd ~ to start at your home directory.
  2. find . -name "*.txt" — see every text file below you. Notice it reaches into subfolders on its own.
  3. Pick a file you know has a certain word, then grep "thatword" thefile.
  4. Now try grep -rin "thatword" . and watch it search everything at once, showing files and line numbers.

find searches by file name; grep searches for text inside files.

In find . -name "*.log", what does the . mean?

Start searching here — the current directory — and all folders beneath it.

What do -i, -r, and -n do for grep?

Ignore case, search recursively through subfolders, and show line numbers.

What does the name grep actually stand for?

Global / regular expression / print — from the g/re/p command in the old ed editor.
