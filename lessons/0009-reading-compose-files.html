Linux Command Line Confidence · Lesson 0009

Reading a Docker Compose File

You've pasted these into your NAS and they worked. Now let's make every line mean something.

The goal: stop pasting, start reading

You can already get a container running by copying someone's docker-compose.yml. That's a real skill — but it means when something breaks, or you want to change a port, you're guessing. This lesson has one job: by the end, you can point at any line in a compose file and say what it does.

Nothing here touches your NAS. Reading and writing a compose file is just editing a text file — completely safe. Deploying one changes things, and we'll treat that carefully at the end.

YAML in sixty seconds

A compose file is written in YAML, a format for describing structured data in a way humans can read.

Name origin: YAML launched in 2001 as "Yet Another Markup Language" — a joke, since markup languages were everywhere at the time. By 2002 its creators renamed it to the recursive "YAML Ain't Markup Language," to make the point that it's for data, not documents.1 Both readings are still in circulation.

Three rules cause virtually every YAML error you'll ever hit:

RuleWhy it bites
Indentation means nestingHow far a line is indented is what makes it "belong to" the line above. It isn't decoration — it's the structure.
Spaces only, never tabsA Tab character is invalid for indentation in YAML. This is the classic invisible error: it looks fine, it won't load.
key: value needs the spacekey:value is wrong; key: value is right. The space after the colon is required.

And one piece of notation: a leading - marks a list item. So this…

ports:
  - "8080:80"
  - "8443:443"

…means "ports is a list, and here are two entries." Wherever you see a stack of dashes, you're reading a list.

The skeleton

Nearly every compose file is the same three-level shape:

services:          <- level 1: "here come the containers"
  jellyfin:        <- level 2: a name YOU choose for this container
    image: ...     <- level 3: the settings for that container
    ports: ...
  another-app:     <- a second container, same indent as the first
    image: ...

That's it. services: holds one block per container; each block's name is yours to pick; everything indented under it configures that one container. Once you see this shape, even a 200-line file is just more of the same.

The five keys you'll always meet

KeyWhat it does
imageWhich prebuilt container to download and run — the app itself.
portsWhich door on your NAS opens into the container.
volumesWhich folder on your NAS the container can store files in.
environmentSettings passed into the app (timezone, user IDs, passwords).
restartWhat should happen after a crash or a NAS reboot.

The one rule that prevents most mistakes

For both ports and volumes: the left side is your NAS, the right side is inside the container. Outside : inside. Host : container.

So "8096:8096" means "port 8096 on my NAS leads to port 8096 inside the container." And /volume1/docker/jellyfin/config:/config means "the folder /volume1/docker/jellyfin/config on my NAS appears as /config to the app."

The right-hand side is fixed by whoever built the image — the app expects its config at /config, so you leave that alone. The left-hand side is yours to change. That single insight is what lets you safely adapt a tutorial's file to your own NAS: change the left, leave the right.

It's also why port clashes happen. If two containers both want 8096 on the left, the second one fails — two things can't answer the same door. Change the left side to something free (say 8097:8096) and it works. Note that DSM itself already occupies some ports, 5000 and 5001 among them, so avoid those on the left.

Decoding a real one

Here's a file of the shape you've been pasting. Read it top to bottom — you now know every rule it uses:

services:
  jellyfin:
    image: jellyfin/jellyfin:latest
    container_name: jellyfin
    ports:
      - "8096:8096"
    volumes:
      - /volume1/docker/jellyfin/config:/config
      - /volume1/media:/media:ro
    environment:
      - TZ=Europe/London
      - PUID=1026
      - PGID=100
    restart: unless-stopped

Line by line:

  • jellyfin: — the name you chose for this container.
  • image: jellyfin/jellyfin:latest — download the jellyfin image. The part after the colon is the tag (the version); latest means newest.
  • container_name: — a fixed, friendly name so it isn't auto-generated.
  • ports: - "8096:8096" — a list with one entry: NAS port 8096 → container port 8096.
  • volumes: — two entries. Config lives in a real folder on your NAS (so it survives a container rebuild), and your media folder is mounted at /media. Note the :ro on the end of that second one — read-only, so the container can view your media but never modify it. A genuinely good habit.
  • environment: — settings handed to the app. TZ is the timezone. PUID/PGID are a Synology-flavoured convention: the user and group ID the app should act as, so the files it creates have permissions you can actually use. (That's Lesson 0008 showing up in the wild.)
  • restart: unless-stopped — see below.

The restart options are worth knowing properly, because this is what determines whether your apps come back after a NAS reboot:2

ValueBehaviour
noNever restart automatically (the default).
on-failureRestart only if it crashed with an error.
alwaysAlways restart — even if you deliberately stopped it and Docker later restarts.
unless-stoppedRestart automatically, except if you stopped it on purpose. Usually what you want on a NAS.

If your copied files start with version:, delete that line

Older tutorials — and there are thousands — begin with something like:

version: "3.8"
services:
  ...

That top-level version key is obsolete. Modern Docker Compose ignores it entirely and always validates against the newest schema; using it just produces a warning.3 Delete the line and the warning goes away — nothing else changes.

It's also a useful dating device: if a tutorial still shows version:, it hasn't been updated in years, so treat the rest of its advice with a little more suspicion too.

Related naming note: the tool was once a separate program called docker-compose (with a hyphen). It's now built into Docker as a subcommand, docker compose (with a space). Both the filename docker-compose.yml and the newer compose.yaml are recognised — on Synology's Container Manager you'll usually see the former.

On your NAS specifically

  • In DSM 7.2+, the Docker package is called Container Manager, and its Project feature is where compose files live — you paste your YAML there rather than needing SSH.
  • Paths on the left of a volumes: line should be full NAS paths starting with the volume number, like /volume1/docker/appname/config.
  • Keeping each app's data under /volume1/docker/<appname>/ is the widely used convention, and it makes backups obvious.
When you do deploy: create a new Project rather than editing one that's currently working. If a new file has a mistake, the worst case is that one new container fails to start — your existing setup is untouched. That's the compose equivalent of the sandbox habit from Lesson 0006.

Try it — zero risk

The best practice material is the files you already have:

  1. Open Container Manager on your NAS and look at an existing Project's compose file (or find a docker-compose.yml you saved).
  2. Name every top-level key you see. Anything that isn't image, ports, volumes, environment, or restart — note it down to ask about.
  3. For each ports line, say out loud which number is your NAS and which is the container.
  4. Check whether it starts with version: — now you know that line does nothing.
  5. Find one thing you could safely change (a left-hand port, a timezone) without breaking anything.

Check your recall

Answer from memory first, then reveal.

In "8096:8096", which side is your NAS and which is the container?

Left is your NAS (the host), right is inside the container. Outside then inside.

Why must you never use Tab characters to indent YAML?

Tabs are invalid for YAML indentation — only spaces work, and the error is invisible.

What does a leading - mean in a YAML file?

It marks a list item, so several dashes together form a list.

A tutorial's file starts with version: "3.8". What should you do?

Delete it — the key is obsolete and ignored, and it dates the tutorial.

What does restart: unless-stopped mean?

Restart automatically after crashes and reboots, unless you stopped it deliberately.

What does adding :ro to the end of a volume line do?

Mounts that folder read-only, so the container can read but never modify it.
