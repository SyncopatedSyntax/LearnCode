Pipes & Redirection

The moment small commands snap together into something powerful — >, >>, and the mighty |.

The idea that makes the terminal powerful

Every command quietly has two ends: an input and an output. Until now, output has always landed on your screen. This lesson is about redirecting that flow — into a file, or into another command.

That's the whole Unix philosophy in one move: instead of one giant program, you get lots of small, sharp tools — each doing one thing well — that you snap together. You already know several (grep, sort-to-come, less); now you'll connect them.

Mostly safe. Pipes just move data between commands — harmless. The one sharp edge is >, which can overwrite a file; it's flagged clearly below.

> — send output into a file

Put > after a command to write its output to a file instead of the screen:

$ ls > files.txt      # the listing goes into files.txt, not the screen

Mnemonic: > is an arrow pointing at where the output should go.

> overwrites. If files.txt already exists, its contents are replaced — silently, no undo. Same clobber risk as cp/mv in Lesson 0006. Don't point > at a file you want to keep.

>> — add to the end of a file

Double the arrow to append instead of overwrite — it keeps what's already there and adds to the bottom:

$ echo "backup finished" >> log.txt

Mnemonic: two arrows = "add on." It's the safe cousin of >.

That example uses a new little command: echo simply prints back whatever you give it.

$ echo "hello"
hello

Name origin: echo echoes your words back — like a shout in a canyon. Paired with >>, it's the quick way to add a line to a file.

| — the pipe: feed one command into the next

This is the star of the lesson. A pipe (|) takes the output of the command on its left and hands it straight to the command on its right as its input:

$ ls | wc -l      # feed the file listing into a line-counter → number of items

Here wc -l is a new tool: wc is word count, and -l makes it count lines. Pipe your file listing into it and you've counted your files.

Name origin — the good one: it's literally called a "pipe" because data flows through it like water through plumbing, from one program into the next. That plumbing metaphor is exactly what its inventor had in mind — a chain of pipes is called a pipeline.

Snapping them together

The payoff is combining tools you already know. Read each of these left to right — output flows rightward through every |:

PipelineAnswers
grep "error" server.log | wc -lHow many lines contain "error"?
grep "error" server.log | lessLet me page calmly through the matches (grep + less)
ls | sortList the folder, alphabetically sorted
history | grep sshWhich ssh commands did I run before?

Two more new helpers appear above: sort (arranges lines in order — literally "sort," with -n for numeric and -r for reverse) and history (lists the commands you've run). Notice you didn't need to learn much — you're recombining what you already had.

Try it — all harmless

$ echo "first line" > practice.txt      # create the file with one line
$ echo "second line" >> practice.txt     # append a second
$ cat practice.txt                       # see both lines
$ ls | wc -l                             # count items in this folder
$ grep "line" practice.txt | wc -l       # how many lines contain "line"?
$ rm practice.txt                        # tidy up (your Lesson 0006 skill)

Watch the difference: run the first echo (with single >) twice and the file still has one line — it keeps overwriting. Swap to >> and the lines pile up. That contrast is the whole lesson in two keystrokes.

Check your recall

Answer from memory first, then reveal.

What's the difference between > and >>?

> overwrites the file; >> appends to the end, keeping what's there.

In plain words, what does | do?

Feeds the output of the command on its left into the command on its right as input.

What does ls | wc -l tell you?

How many items are in the current folder — it counts the lines of the listing.

Why is > a little dangerous?

It overwrites the target file silently, with no undo — use >> to add instead.

What does echo do?

Prints back whatever text you give it — handy for adding a line to a file.
