Linux Command Line Confidence · Lesson 0001

Finding Your Way Around

Four commands that work in every terminal you'll ever open — your own machine, a GitHub Codespace, or your Synology NAS over SSH.

Why this first

Every terminal session starts the same way: you're "in" some directory (folder), and you can't do much until you know where that is and how to move around. This is true whether you're poking around your Synology NAS, working inside a cloned GitHub repo, or sitting at any Linux box. Get comfortable with these four commands and the rest of the terminal stops feeling like a black box.

Everything in this lesson is read-only. None of these commands can change, move, or delete anything. Safe to run on your own machine, a spare Linux box, or your NAS over SSH.

One habit that makes these stick: every command name is short for something. I'll point out what as we go — it turns a cryptic couple of letters into a word you can actually remember. The full list lives in the Command Name Origins glossary.

The four commands

pwd — print working directory

Answers one question: where am I right now? Run it with no arguments:

$ pwd
/home/yourname

That output is your working directory — the folder the shell currently considers "here." Every relative path you type is interpreted starting from this.

Name origin: pwd = print working directory — the three letters are the initials of its three-word job. Say the words and the command explains itself.

ls — list

Shows what's inside the working directory.

Name origin: ls = list, with the vowels knocked out — the classic Unix habit of squashing a word down to save keystrokes.

$ ls
Documents  Downloads  Pictures

Two flags you'll use constantly:

  • ls -a — show hidden files too (anything starting with ., like .ssh or .bashrc)
  • ls -l — "long" format: permissions, owner, size, and modified date for each item

Combine them: ls -la is probably the single most-typed command in any Linux terminal.

$ ls -la
drwxr-xr-x  5 you  staff   160 Jun 12 09:14 .
drwxr-xr-x  9 you  staff   288 Jun 10 18:02 ..
-rw-r--r--  1 you  staff   220 Jun 10 18:02 .bashrc
drwxr-xr-x  3 you  staff    96 Jun 12 09:14 Documents

The first character of each line tells you the type: d for directory, - for a regular file. The . and .. entries always appear — they mean "this directory" and "the parent directory."

cd — change directory

Moves your working directory somewhere else.

Name origin: cd = change directory — the initials of the two words, saying exactly what it does.

$ cd Documents
$ pwd
/home/yourname/Documents

A few shortcuts worth memorizing:

  • cd .. — go up one level, to the parent directory
  • cd ~, or just cd with nothing after it — jump straight home
  • cd - — jump back to wherever you were before your last cd

Absolute vs. relative paths

This is the idea that ties the other three together.

  • An absolute path starts with / and means the same thing no matter where you currently are — e.g. /home/yourname/Documents.
  • A relative path has no leading / and is interpreted starting from your current working directory — e.g. Documents, or ../Downloads (up one, then into Downloads).

When in doubt, run pwd first. It's the anchor for every relative path you're about to type.

Try it

Open a terminal — your own machine is fine, you don't need the NAS for this — and work through this, checking your prediction with pwd after each step:

  1. Run pwd. Note where you are.
  2. Run ls -la. Find one hidden file (starts with .).
  3. cd into any directory you saw listed.
  4. Run cd .. and confirm with pwd that you're back where you started.
  5. Run cd - twice in a row. Notice it toggles between the last two directories you were in.

Check your recall

Don't scroll back up — answer from memory, then reveal.

What does pwd do?

Prints the full path of the directory you're currently in.

What's the difference between ls -a and ls -l?

-a shows hidden files (dotfiles); -l shows the long format with permissions, owner, size, and date.

What does cd .. do?

Moves you up one level, into the parent of your current directory.

How can you tell an absolute path from a relative one, just by looking at it?

An absolute path starts with a leading slash (/); a relative path doesn't.
