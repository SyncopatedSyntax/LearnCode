Linux Command Line Confidence · Lesson 0005

Getting Help Yourself

Every command carries its own manual. Learn to read it and you stop needing anyone — including me — to look things up.

Why this is the multiplier

You can now navigate, connect, read, and search — all by recalling specific commands. This lesson is different: it's the skill that lets you figure out every other command on your own. That's the real goal of the whole mission — not memorising a list, but being unafraid because you can always ask the machine itself.

Completely harmless. Everything here just displays documentation. Nothing to break, on your computer or the NAS — the safest lesson yet.

command --help — the quick reminder

Most commands will summarise themselves if you add --help:

$ ls --help
Usage: ls [OPTION]... [FILE]...
List information about the FILEs ...
  -a, --all      do not ignore entries starting with .
  -l             use a long listing format
  ...

Fast, prints right in place, and perfect when you just need to remember a flag.

A dash convention worth knowing

Look at that -a, --all line — it quietly explains every flag you've met so far:

  • One dash + one letter = the short form: -a, -l, -r, -i. Fast to type.
  • Two dashes + a whole word = the long form: --all, --recursive. Slower, but self-explaining.

Many flags have both, and -a and --all do exactly the same thing. That's why --help is itself two dashes and a word — it's just the long-form help flag (its short form is often -h).

Name origin: --help is literally the word "help" in long-form flag style. No decoding needed.

man — the full manual

When --help's summary isn't enough, man opens the command's complete manual page:

$ man ls
You already know how to drive this. man opens the manual in less — the exact pager from Lesson 0003. So: Space to scroll, /word then Enter to search, and — the one that saves everyone — q to quit back to your prompt.

Name origin: man = manual. It shows the manual page ("man page") for a command.

How to read a man page

Every man page follows the same skeleton. Once you know the headings, you can jump straight to what you need instead of reading top to bottom:

SectionWhat's there
NAMEThe command and a one-line description
SYNOPSISThe shape of the command — how to assemble it
DESCRIPTIONThe full explanation, and every option
EXAMPLESReady-to-copy real uses (when present — jump here first)

Decoding the SYNOPSIS

The SYNOPSIS uses a small notation that trips people up until someone explains it. For example:

ls [OPTION]... [FILE]...
  • Square brackets [ ] = optional. [FILE] means you may give a file, but don't have to.
  • Three dots ... = "and you can repeat this." [FILE]... means zero, one, or many files.
  • Plain words = type them as-is.

So that line reads: "ls, optionally followed by any number of options, optionally followed by any number of files." That notation is the same across almost every man page.

When you don't even know the command's name

This is the hidden gem. man -k (or its twin apropos) searches the one-line descriptions of every installed manual for a keyword — so you can find a command by what it does:

$ man -k "disk space"
df (1)    - report file system disk space usage
du (1)    - estimate file space usage

It's Lesson 0004's idea — searching — turned on the manuals themselves. (The (1) just marks which section of the manual it's in; section 1 is everyday user commands.)

Name origins: the -k is for keyword. And apropos is an actual English word — borrowed from French — meaning "concerning" or "with regard to." apropos disk literally asks for commands "concerning disk." A rare command whose name is a whole word with a real meaning.

One honest note for the NAS

Minimal systems often skip man. To save space, many stripped-down setups — NAS boxes very much included — don't install the full manual pages. If man says "command not found" or comes up empty on your Synology, that's normal: fall back to --help, which is built into the commands themselves and almost always works. On your own computer, man will be there.

Try it

  1. Run ls --help and find a flag you haven't used yet.
  2. Run man ls. Scroll with Space, search for -l by typing /-l then Enter, then quit with q.
  3. In that man page, find the SYNOPSIS line and read it using the bracket/dots notation above.
  4. Run man -k time (or apropos time) and skim how many commands mention "time."

Check your recall

Answer from memory first, then reveal.

You're inside a man page and your prompt has vanished. How do you get out?

Press q — man pages open in less, so the same quit key applies.

In a SYNOPSIS, what do [ ] and ... mean?

Square brackets mean optional; three dots mean the item can be repeated.

You want a command but only know what it should do. What do you run?

man -k keyword (or apropos keyword) to search manuals by description.

man isn't installed on your NAS. What's the fallback?

Add --help to the command — it's built in and works almost everywhere.
